## 1. 一句话结论

双麦克风、按座位绑定的因果串音对消方案可行，并已有可运行原型。现行默认是 16 ms 窗（N=256 / hop=64）+ 因果 GSC（从零自适应、带空间门控）+ 动态后置抑制 β=1.00。单说 10 段平均可把对侧串音再压约 **14.93 dB**（固定 λ=0.80 时为 13.33 dB），本路目标基本无损。

预期是「减轻串音」，不是把对侧抹掉。叠说、回声消除（AEC）、ASR 串词三项仍未验证。

## 3. 产品链路

**两路怎么进：** 车内两只麦克风——`mic_raw` = 主驾麦、`mic2_raw` = 副驾麦（通道约定已用单说能量比和 TDOA 符号核对）。音频按 16 kHz / 16-bit little-endian / 单声道处理。实采 PCM 无文件头、无采样率标注，16 kHz 是据音高与 50 cm 麦间距几何（直达时差约 1.1 ms）反推的假设；**若实际采样率不是 16 kHz，全部时间与 dB 结论都要重算**。

**两路怎么出：** 两路一起进对消器，输出绑座位——主驾输出 ≈ 干净的主驾语音 + 被压低的副驾串音，副驾输出相反。只有一路被判定「本座位单说」时，该路直接退回近麦（目标保护），另一路继续对消。

**和云端 ASR 的关系：** 处理后的两路清音作为云端 ASR 的输入，云端不必感知对消的存在；收益预期是降低 ASR 侧串词。两点要说清：

1. 算法时延 16 ms，对云端 ASR 通常可接受；
2. **评测没有 ASR，本轮结论全部基于能量 / 相关 / 语谱，没有转写证据。** 「串词解决没有」目前无法判定。

**服务对外形态：** Web UI 选 15 段实采试听（主驾 / 副驾各「原麦 vs 输出」）。滑杆是动态因子 β：0 为固定 λ=0.80，默认 1.00；另有「只做 GSC」开关。HTTP API 为 `POST /api/cancel`（两路单声道 wav/pcm 进，zip 返回两路输出）。采样率不是 16 kHz 的 WAV 会被拒绝，不会擅自重采样。

## 4. 算法组成

整条链路是三层，全部因果、不用声纹。

**第一层：因果 STFT 域 GSC（广义旁瓣抵消），从零自适应。**
每段开始时阻塞矩阵滤波器 H 从 0 起步，逐帧更新（步长 mu=0.25，先输出本帧、再更新系数），因此不需要预先标定，换人换坐姿能自己收敛。阻塞矩阵的相对传递函数（RTF）用这批单说段估计（演示段单说用 LOSO，两人段 / API 用池化 RTF）。API 若没有这些单说段，无法冷启动一套 RTF，这是已知限制。

**第二层：空间门控目标保护（本方案的成败关键）。**
每帧用 ILD（两麦能量差）+ 帧级 GCC-PHAT 时差判断「谁在说」。判定为「本座位单说」时，该路输出退回近麦，防止自适应滤波器把目标自己消掉。评测已证明这层不是可选项：同样的 GSC 不加门控（「先标定常开」），单说 SI-SDR 会掉到约 7–8 dB（最差段 1.79 dB）；加门控后目标保真恢复到与近麦几乎重合。门控会偶发漏判（`20261126_153134` 段即一例）。

**第三层：因果残差 Wiener 后置抑制，强度可随对侧座位活动变化。**
对 GSC 输出再做一次同帧 STFT 的残差 Wiener / 时频掩蔽。先选出固定强度默认 λ=0.80：λ 从 0 提到 0.80，单说平均 CTA 约 +5.3 dB，本路几乎不动；λ=0.90 / 1.00 对侧残差开始出现音乐噪声迹象，故固定档停在 0.80（出处：`RESULT-postfilter.md`）。

在此基础上，把 λ 改成随对侧座位空间活动变化的 λ(t)。控制量**不是对侧原麦 RMS**（两路麦都会收到两个人）。每一帧组合 ILD、TDOA 和阻塞支路能量，得到：

\[
\lambda(t)=\mathrm{clip}(0.80+\beta\,\delta(t),\;0,\;1)
\]

β=1.00 时：对侧空间占优则 λ 升向 1.00，本路单说或静音保持 0.80，叠说回退到约 0.60。β=0 与固定 λ=0.80 逐样本一致。滑杆只做 \(y_{\mathrm{base}}+\beta\,y_{\mathrm{exc}}\)，不重跑 GSC。

## 5. 关键评测数字及出处

评测数据：15 段实采（只主驾 5 / 只副驾 5 / 两人会话 5），近麦能量 VAD 语音帧。CTA = 对侧输出相对对侧原麦的能量衰减（越高越好）；SI-SDR / 相关 / 能量比 = 本路输出相对近麦的目标保真。

### 5.1 现行配置（N=256，动态 β=1.00）单说 10 段 —— 出处 `RESULT-dynamic-postfilter.md`

| 指标 | 固定 λ=0.80（β=0） | 现行动态 β=1.00 | 变化 |
|---|---:|---:|---:|
| 单说 10 段平均 CTA | 13.33 dB | **14.93 dB** | **+1.60 dB** |
| 只主驾 / 只副驾平均 CTA | 13.45 / 13.22 | 15.69 / 14.17 | +2.24 / +0.95 |
| 单说平均 / 最差能量比 | −0.12 / −0.42 | −0.12 / −0.42 | 几乎不变 |
| 单说平均 / 最差相关 | 0.997 / 0.980 | 0.997 / 0.980 | 不变 |
| 单说平均 / 最差 SI-SDR | 27.15 / 13.85 | 27.16 / 13.85 | 几乎不变 |
| 单说平均 LSD | 0.96 | 0.96 | 不变 |

这不是把 λ 全局拧到 1.00。固定 λ=1.00 虽然 CTA 到 15.82 dB，但 LSD 升到 1.23、残差峰值/中位数到 33.59，未通过保真门槛。动态方案把加力限制在对侧空间占优的帧。

### 5.2 固定后置选值（512 窗基准）—— 出处 `RESULT-postfilter.md`

- λ 从 0 → 0.80：单说平均 CTA 7.89 → 13.16 dB（+5.27），本路能量比仅 −0.14 dB、相关 0.998。
- 交替区（两人段）：主驾交替 CTA 6.07 → 10.89 dB，副驾交替 7.79 → 11.75 dB。
- 拒绝把固定 λ 设为 1.00 的理由：对侧残差音乐噪声线索跳升（峰值/中位数 48.2，相对 0.80 的 32.2）。

### 5.3 窗长扫描与最终选择 —— 出处 `RESULT-window.md`

- 预写门槛（单说平均 CTA 降幅 ≤0.5 dB）下的最短通过窗是 **N=208 / 13 ms**（CTA 12.86）。**这是扫描推荐，不是现行默认。** 该档平均还掩盖了只主驾约 −2.24 dB、只副驾约 +1.62 dB 的不均衡。
- 用户最终选定 **N=256 / 16 ms**：平均 CTA 不低于 32 ms 基线的最短窗（13.33 vs 13.16，+0.17 dB）。
- 明确不推荐：8 ms（N=128，CTA 仅 9.47）与 12 ms（N=192，CTA 降幅超预算）。更长窗还能再涨一点 CTA，但与时延目标相反，不作默认。

### 5.4 上限的空间解释 —— 出处 `RESULT-gsc.md`

- 先天近远差只有约 4–7 dB。
- 线性因果上界：同段过拟合 Wiener（不是线上方案）也只有约 6.5 dB CTA；在线 GSC 能达到或略超它，所以线性路子再挖潜力有限，才加了非线性后置。
- 两麦间距 50 cm，房间反射明显（3–5 ms 反射峰）。标定必须避开约 −3.3～−3.4 ms 的反射峰，不能把它当成直达时差。
- 残留仍听得见，也可能让 ASR 串词。

## 6. 明确不推荐 / 已失败的做法

| 做法 | 实测结果 | 出处 |
|---|---|---|
| 朴素延时相减（把另一路当干净参考减） | CTA 为负（−1.69 / −2.58 dB），目标也被伤 | `RESULT-gsc.md` |
| 固定时差 LCMV | 目标能量被压掉约 4 dB，串音也没压掉 | `RESULT-gsc.md` |
| 固定 RTF / 跨段标定滤波器 | 目标保真好但 CTA 仅约 1 dB，头位一变就不泛化 | `RESULT-gsc.md` |
| GSC 先标定后「常开、不关门」 | 会伤目标（单说 SI-SDR 平均 7–8 dB，最差 1.79 dB） | `RESULT-gsc.md` |
| 把固定 λ 拉满到 1.00 | 音乐噪声与谱伤上升；不要用它替代动态 β=1.00 | `RESULT-postfilter.md`、`RESULT-dynamic-postfilter.md` |
| 窗长 8–12 ms | 明显妥协，短窗瓶颈是频率分辨率 | `RESULT-window.md` |
| 用对侧原麦 RMS 去调后置强度 | 不可行：远麦同样带着本路泄漏 | `RESULT-dynamic-postfilter.md` |
| 同段 Wiener（约 6.5 dB） | 只是线性上界参考，不是线上方案 | `RESULT-gsc.md` |

## 7. 限制与未验证项

1. **AEC 未验证。** 这批实采的 `echo_ref` 几乎静音（无扬声器回放）。量产若有导航 / 通话外放，必须先 AEC 再进本对消，且两路必须同一时钟、成对处理。
2. **叠说未定量。** 现有重叠时长每段只有约 0.85–1.24 s（平均 1.06 s），无干净参考，无法把「压了对侧」和「伤了本路」拆开。对侧谐波在语谱上仍可见。不能声称解决了双讲。
3. **ASR 串词未验证。** 评测无转写，不能点名哪些词串进了对侧。
4. **门控偶发漏判。** `20261126_153134` 是已知最差段（现行最差 SI-SDR 仍约 13.85 dB）。可闻损伤小但不是满分。
5. **衰减仍有上限。** 若 ASR 串词仍超标，出路是更近的麦、更多通道，或本轮没做的非线性 / 模型方法（例如空间神经网络分离、在线 BSS）。
6. **采样率假设。** 无头 PCM 按 16 kHz 解读；若实际不是，全部时间 / dB 要重算。
7. **短段包含从零收敛过程**；换车、换人、换坐姿需要持续自适应，一次性标定不可用。
8. **API 冷启动。** API 侧阻塞矩阵用池化 RTF，没有这批单说段时无法自行冷启动。
9. **原型是文件 / 会话演示，不是实时麦克风采集流。**

## 8. 原型如何运行

详见仓库根目录 [README.md](../README.md)。摘要：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
PYTHON=.venv/bin/python ./start.sh
```

默认打开 http://127.0.0.1:8766/ 。端口被占用时用 `PORT=8767`。首次启动会读取 `pcm/` 预计算 15 段，结果写到本地 `cache/`（不进仓库，可再生成）。

- UI：`/`
- 健康检查：`/api/health`
- 片段列表：`/api/sessions`
- 对消接口：`POST /api/cancel`

复现评测可用根目录的 `run_postfilter_eval.py`、`run_window_eval.py`、`run_dynamic_pf_eval.py`，它们默认读取本仓库的 `pcm/`。
