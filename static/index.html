两路成对处理：主驾输出保留主驾、减轻副驾串音；副驾输出相反。 算法是评测推荐的因果 STFT 域 GSC（从零自适应）+ 空间门控，再加一层可调的残差后置抑制，不用声纹。 这是文件/会话演示，不是实时麦采集。

这一条滑杆是动态强度 β，不是以前那条固定 λ。 β=0：整段都用固定后置 0.80（当前基线）。 β 越大：只在「对侧座位空间上正在说话」时把抑制往上加（最高到 1.0）；两边叠说时有上限，会往 0.60 收回，避免把本路压掉；本路单说时保持 0.80。 控制量用 ILD、到达时差和 GSC 阻塞支路能量，不是对侧原麦音量。 建议默认 1.00（单说平均 CTA 约 14.93 dB，比固定 0.80 多约 1.6 dB，本路几乎不变）。 拖动后立刻作用于两路输出，不会重跑 GSC。

评测结论（摘自 RESULT-dynamic-postfilter.md，不是本页现场测量）

  • 窗长仍是 N=256、hop=64，算法时延 16 ms。后置改为动态：默认 β=1.00。β=0 即原来的固定 λ=0.80。
  • 默认档单说 10 段平均 CTA 约 14.93 dB，比固定 0.80 的 13.33 dB 多约 1.6 dB。本路能量比约 −0.12 dB、相关约 0.997、LSD 约 0.96，与固定 0.80 几乎相同。交替区 CTA 约 10.7 / 13.0 dB。
  • 这比把 λ 全局拧到 0.90 或 1.00 更划算：固定 0.90 的 CTA 还略低（14.53），LSD 已经升高；固定 1.00 虽然 CTA 到 15.82，但 LSD 和音乐噪声线索越出门槛。动态方案只在对侧占优时加力，叠说有 0.60 上限。
  • 预期仍要收在「再减轻一截串音」，不是「把对侧抹掉」。重叠区没有干净参考。这批没有扬声器，回声消除尚未验证。

v1.3 限制

  • 不是实时麦克风流，只对已有录音或上传的完整文件做对消。
  • 在线路径从 H=0 自适应，短段会包含收敛过程；阻塞矩阵 RTF 用这批单说段估计（与评测相同）。换车、换麦、头位大动后需要重新适应，不能一次标定冻住。
  • 后置抑制是因果残差 Wiener，强度随对侧座位的空间活动估计变化。滑杆只混合预先算好的「固定 0.80」和「动态增量」，不重跑 GSC。
  • 这批实采几乎没有扬声器回放，回声消除尚未验证。
  • 未接转写 / ASR，不能在本页点名「串了哪些词」。

HTTP API

把两路单声道 wav 或无头 pcm 成对 POST 上来，返回一个 zip（driver_out.wav、passenger_out.wav、info.json，以及 GSC / 固定 0.80 / 动态增量对照 wav）。采样率必须是 16 kHz；pcm 按 16-bit LE 解读。主参数是表单字段或查询参数 beta（0–1，默认 1.00；0=固定 λ=0.80）。旧参数 strength 仍表示固定 λ（0=只做 GSC）。

curl -sS -X POST http://127.0.0.1:8766/api/cancel \
  -F "mic_driver=@mic_raw.wav" \
  -F "mic_passenger=@mic2_raw.wav" \
  -F "beta=1.00" \
  -o cancel_out.zip

也可以用字段名 mic_raw / mic2_raw。健康检查：GET /api/health。片段列表：GET /api/sessions。书面结论：RESULT-dynamic-postfilter.md（动态后置）、RESULT-window.md（窗长）、RESULT-postfilter.md（固定后置强度）。
